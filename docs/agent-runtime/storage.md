# 存储：区分可以重取的数据与不能重写的历史

本地文件并不都属于缓存。行情可以重新获取，用户选择不能靠默认值重建，旧报告也不能用今天的模板和价格替代。存储层先划分这些责任，再决定怎样写入、恢复和清理。

Storage 接收带身份和版本的内容，交付已提交的记录、固定引用或明确失败；Source 解释数据来源，Runtime 绑定设置和存储，Agent 管理会话生命周期。UI 不自行拼接路径或修改文件。这样，换一个入口不会同时改变持久化规则。

## 四类数据，对应不同的保留责任

设置、凭证引用和观察组合是用户维护的持久状态。公开行情的最新快照可以用于缓存；被研究引用的行情版本则必须保留。会话、比较、回测和报告属于显式成果，不能因超过缓存期限而自动删除。私有账户与订单有独立宿主和存储边界，不混入公开行情、默认研究上下文或分享副本。

观察组合只保存标的与分组，不等于账户持仓。旧 `.ohquant/portfolio/` 文件是遗留用户数据，只在用户主动迁移时读取，不形成持续依赖，也不自动删除。具体文件入口见 [Storage 模块](../../src/storage/README.md)，本页维护保留与提交语义。

这种分类增加了磁盘占用，也意味着“清缓存”不能解决全部空间问题。人工删除研究归档后，旧引用可以失效，但系统不能静默换成新数据以维持绿色状态。

## 写入成功必须对应明确的提交点

工作区 `.host/` 是私有进程登记与所有权元数据，包含本机连接能力，不属于行情缓存或会话 journal。启动锁与执行锁只在确认旧进程死亡后回收，不能按 mtime 抢占；损坏或未知格式保留。就绪登记经原子替换发布，正常停止仅移除匹配的本实例登记。机制与权限边界见[工作区 Host](./host.md)。

设置与观察组合采用版本检查：草稿绑定读取时的文件版本，写入时在锁内重新比较。另一窗口已经保存时，旧草稿应报告冲突并保留编辑内容，而不是覆盖新值。损坏文件也不能被当成空配置重新保存。

锁协调写入者，原子替换让读者看到完整版本，两者不能互相替代。默认实现先写唯一临时文件，再同步并替换目标；失败不提前发布成功状态。Windows 的短暂文件占用只允许有限重试，不先删除原文件，也不无限阻塞界面。长时间网络操作不放在短同步写锁里。

设置提交与连接验证也必须分开。并发冲突需要重新读取；临时占用可以重试；格式损坏需要修复或恢复。把这些情况统一成“重试保存”，容易把可恢复冲突变成数据覆盖。

## 最新缓存与研究版本回答不同问题

最新快照同时提交数值、来源、时间与响应成员。新鲜度既看抓取时间，也看请求覆盖；积累了更早价格，不代表最近响应包含这些日期。普通研究复用与陈旧回退都受最近成功响应的日期集合约束，不能用旧行补出貌似完整的新响应。

同日期修订可以替换缓存值，但旧研究版本不随之改写。前复权历史可能整体变化，因此当前响应不能与旧尺度直接拼接；未知价格口径和缺失成交额也不能被补成确定值。来源解释见[数据契约](../quant-harness/source-data-providers.md)。

研究引用绑定实际输入与不可变版本。历史截止查询只接受已经提交、且在截止前观察到的响应；它证明应用保存过什么，不证明供应商当时首次发布了什么，也不消除存活偏差。

归档文件存在还不够。进程可能在写出版本后、提交最新快照前退出，因此 Bars 通过有效 head 或内容绑定的提交标记识别已提交修订；基金 NAV 以提交标记完成为准。未提交的孤立文件不参与恢复。旧格式无法补出过去没有记录的提交证据，兼容读取须保留这个限制。

## 会话保存事实，研究状态按事实重建

会话 journal 保存分支、用户输入和工具结果。完整分支复制、摘要与 leaf 移动按各自提交边界完成；失败不先切换内存状态。重复身份、缺父节点或截断记录不能被部分接受，列表可以隐藏坏记录，但保留原文件。

会话提交在同一写锁内检查版本并异步写入、同步落盘、原子替换。Windows 遇到短暂占用时，替换重试让出事件循环，使并发读取能够释放句柄；重试仍有时限，不删除已提交文件。替换前取消会清理临时文件并保留旧版本；替换已成功则以新文件为提交事实，不把随后到达的取消解释成回滚。

研究完成状态从当前分支及固定输入重新投影，不另存一份会漂移的真值。归档后来丢失时，核验状态可以退回未知，但不能删除已经发生的事件。摘要减少模型上下文，不取得修改研究事实的权力。

默认会话提交会复制整份文件，成本随历史增长。离线列表的上下文估算与活动模型窗口也可能不同；它们服务导航和预算提示，不是精确恢复承诺。会话机制与取消边界见[运行时](./README.md#pi-integration)。

## Workbench 检查点与模型上下文分工

`.ohquant/workbench/sessions/` 保存版本化的界面投影、稳定身份与原 Quant journal 引用。列表分块读取有界首行，选中后验证完整摘要和身份；替换复用文件锁、存储 revision 与原子写入。新服务读取版本 1 和 2；需要保存中断以外终态的核对状态时才升级该会话至版本 2，后续写入不自动降回版本 1。旧服务不识别版本 2，会拒绝读取并保留原文件；旧版记录在新版仅投影核对状态，读取不迁移。未知版本、损坏或过时写入保留原文件，其他会话仍可访问。这些私有检查点不是不可变报告或工具副作用账本。

重启读取不改写旧记录、不发送请求；遗留 running 投影为 interrupted，已开始但没有保存结果的工具保留为待核对。浏览器草稿只属于视图，不能作为运行真值。格式、兼容性与确认规则见[会话连续性](../quant-harness/workbench-sessions.md)。原 settings、Quant journal 与成果格式不变；新格式没有自动历史导入。

继续未完成运行之前，服务还会根据已有投影和工具注册表检查已完成的副作用；不能证明安全时拒绝继续。运行记录缺失或歧义也要求显式核对，读取不会改写原字节。旧版软件处理其原有版本 1 的记录仍可能遗漏此限制，因此回退前需人工核对或保留新版读取器，不能声称回退安全。检查点并非外部幂等账本，核对后的新提交仍需用户决定，不承诺外部操作不会被重新请求。

## 报告固定字节，恢复核对来源

显式 TSP 采集也复用这一不可变快照，类型为 `tsp-observation`：绑定精确基线，保留工具名、参数、来源、采集时间、原始结果与摘要，以及不可用状态。复核可另外保存所选观察的精确引用、提醒索引与日线窗口/单位；这些字段也参与版本摘要。原始结果留在 Host，不经界面回传或进入通用元数据；服务验证其归属、大小和内容摘要。它只证明本次工具返回的固定字节，不认证供应商数据或有效授权范围。

来源核对使用 `source-check` 私有类型，绑定精确基线、配置行情的 DatasetRef 和公告分页文本；复核仅保存所选来源版本、页码、原文片段和用户确认声明。原 PDF 摘要与提取文本摘要分别保留，原 PDF 二进制不进入归档。它沿用 4 MiB 信封及版本哈希，公告正文不进入通用元数据列表；来源语义、逐页内容摘要和引用归属由服务层验证。

手动假设基线与事件复核可在现有报告快照的 `privateResearch` 字段保留私有输入：请求身份、登记时间、精确前版引用、假设/阈值、事件、证据原文与版本标识、参数和明确决定。该字段独立于 `ArtifactMeta`，不进入通用报告列表或版本元数据列表；保存前检查有界信封与有限 JSON 值，上限 4 MiB。工作区/会话归属、基线语义和证据原文摘要由上层服务核对，存储层不把一个合法哈希当作财务事实认证。

存在该字段时，版本指纹同时覆盖私有输入、HTML 和元数据；删除或改动私有输入会让该版本不可读取，不回退到最新版本。普通旧报告沿用原有指纹格式；后续保存未显式提供私有输入时不自动继承。旧软件不理解新指纹时会拒绝新的私有快照，不能声称可无损回退。私有载荷不是公开分享投影，分享仍须使用独立白名单内容。

报告保存完整快照、元数据和来源关系。新版本追加归档并更新 head，历史列表沿已提交版本链读取；崩溃留下的候选不应显示成完成版本。HTML 浏览视图缺失时，可从同一已核验快照修复，不能重新运行生成器冒充原页面。

恢复允许会话继续追加，但要求原先引用的记录、顺序和分支关系仍然成立。来源损坏时保留报告与当前工作，明确说明无法恢复。列表不可见、移除当前入口和删除不可变归档是不同动作，不能让清理列表顺带抹去研究证据。

完整报告可能含用户原文、组合名称和模拟金额。分享使用独立白名单投影，预览与下载读取同一份版本字节，操作本身不上传。公开投影由[制品设计](../quant-harness/artifacts-design.md)维护，存储保证选中的版本没有被换掉。内容哈希可以发现字节变化，不能认证供应商事实或模型解释。

## 凭证与私有状态不能靠目录名获得保护

设置可能保存明文数据凭证，独立模型登录文件也可能包含 OAuth token。显示脱敏不等于加密；文件权限、备份和对外传输由宿主负责，这些文件不进入公开缓存、报告分享或自动清理。

显式链接 Pi 账号时，WhyJ 保存账号与路径引用；后续令牌轮换在 Pi 文件锁下进行，保留其他账号和权限。退出链接只移除 WhyJ 指针，不删除 Pi 的账号。独立登录与外部链接必须保持不同的所有权语义。

持久化保证最终仍受文件系统约束。现有回归覆盖冲突、取消、损坏和进程终止，不能据此承诺所有设备的断电安全。新用途应先确定所有者、提交点、失败后保留什么、谁有权删除，再选择文件格式。

## 版本化行情观察归档

`archiveHistoricalMinuteObservations` 保存 Tushare `stk_mins` 的一个非空单标的历史 1 分钟响应。原始上海本地时间标签与 09:30 开盘边界标记、股数和人民币成交额、实际来源及观察时间均保留；复权、覆盖和最终状态保持未知。`loadHistoricalMinuteArchive` 只读指定的 `historical-minute-bars` 内容摘要，文件位于 `.ohquant/data/historical-minute-archives-v1/`。归档可验证时间标签和交易日区间，常规分钟的边界转换由 Runtime 完成。

指数分钟行情使用 `archiveDatedIndexMinutes` 写入独立的 `dated-index-minute` 归档。每次捕获固定一个标的和上海日期，保留 TickFlow 的指数点位 OHLC、原始时间戳、量额和本地观察时间。空请求结果也可按摘要读取。归档校验承诺仅到保存的证据，覆盖仍为 `unknown`。`loadDatedIndexMinuteArchive` 按精确摘要读 `.ohquant/data/dated-index-minute-archives-v1/`。供应商条目与 WhyJ 后续计算的昨收涨跌分别保存和标注。

指数日线使用 `archiveDatedIndexDailyBars` 写入 `dated-index-daily` 归档。记录固定上海日期区间、指数点位 OHLC、供应商毫秒时间戳和原始量额。`loadDatedIndexDailyArchive` 按精确摘要读取 `.ohquant/data/dated-index-daily-archives-v1/`。空区间也能按其引用回放，覆盖保持 `unknown`。这个档案为指数日线图和指标窗口提供输入，基准收益档案继续提供其独立的收盘点位和收益契约。

市场截面通过 `archiveMarketCrossSection` 保存一个交易日的 Tushare `bak_basic` 股票池、`daily` 行情和 `daily_basic` 交易统计。各响应保存独立交易日、观察时刻和原始单位。未匹配到股票池的行情仍保留在归档，空响应和字段空值也原样保留。文件位于 `.ohquant/data/market-cross-section-archives-v1/`，通过 `loadMarketCrossSectionArchive` 按精确引用读取并验证摘要。股票池匹配、单位转换和覆盖率统计由回放层处理。观察时间记录采集时刻，历史数据的实际可得时间仍由数据使用方核实。

基准指数通过 `archiveBenchmarkIndexObservations` 保存一份 Tushare `index_daily` 响应。归档记录沪深指数代码、请求范围、采集时刻、按交易日排列的收盘点位、昨收点位、点数变化和供应商涨跌幅。涨跌幅保留百分点单位，缺值和空响应均保留。文件位于 `.ohquant/data/benchmark-index-archives-v1/`，`loadBenchmarkIndexArchive` 按精确引用读取并验证摘要。每次更正和重新采集都有独立的归档版本。数据覆盖和历史发布时间仍为未知。

同一归档族也接收 TickFlow `/v1/klines` 的沪深指数和北证 50 `899050.BJ`。TickFlow 行必须保留原始毫秒时间戳，与上海交易日一致。昨收点位、点数变化和涨跌幅保留为空，后续计算使用独立的 WhyJ 结果。已有 Tushare 归档保持原有结构和摘要。

短线风向标通过 `archiveAuctionBenchmark` 保存一份扶摇观察。归档保留交易日、上海零点、响应组装时刻、实际采集时刻、名单顺序、标签和竞价涨幅百分点，空名单也有独立引用。`loadAuctionBenchmarkArchive` 从 `.ohquant/data/auction-benchmark-archives-v1/` 按种类和摘要读取。变化的名单或采集时刻形成独立版本，历史首发时间及覆盖范围保持未知。

`archiveDragonTigerBoard` 分别保存扶摇全部榜、机构榜和游资榜的单日响应。归档保留榜单类型、返回顺序、上榜区间、席位关联股票、元和小数比例、空榜及缺项。不同榜单、采集时间和修订各有独立引用。`loadDragonTigerArchive` 从 `.ohquant/data/dragon-tiger-archives-v1/` 按精确种类和摘要读取。供应商时间戳和采集时间分别保存。

`archiveDepthSnapshot` 将同一上海交易日的 TickFlow 单标的或批量盘口观测（`/v1/depth`、`/v1/depth/batch`）保存到 `.ohquant/data/depth-snapshot-archives-v1/`。归档保留实际端点、已请求标的、每条盘口的原始时间戳、买卖档价格与数量、显式零和空档。未返回的标的可由请求清单和实际响应对照，数量单位和全市场覆盖仍为未知。`loadDepthSnapshotArchive` 只接受精确版本引用。时效筛选和封板判定使用 WhyJ 的回放逻辑。

`archiveFinancialObservations` 分别保存 Tushare `fina_indicator` 的单标的报告期范围响应，或 `disclosure_date` 的单标的单报告期响应。两类归档各自记录请求、端点和取数时间，保留同报告期多行、返回顺序、修订标记、零值和空值。空响应也有独立归档引用，覆盖标为未知。`loadFinancialObservationArchive` 按种类和内容摘要读取 `.ohquant/data/financial-observation-archives-v1/` 下的精确版本。历史回放需另外证明所用财务指标版本在判断时点已公开。

报告行还可携带基本每股收益与币种证据。`basicEarningsPerShare` 为供应商原值，允许负数、零和空值。`earningsPerShareCurrency` 同时存在并标为 `unknown`。旧版报告行保留原有字段和内容摘要。

`archiveSectorObservations` 按单个交易日分别归档东方财富板块目录 `dc_index` 和单板块成分 `dc_member` 的观察结果。每份归档保留其端点、分类口径、取数时间、原始行顺序和空值，成功的空响应也有精确引用。`loadSectorObservationArchive` 从 `.ohquant/data/sector-observation-archives-v1/` 按种类和摘要读取。后续排行使用归档中的提供商快照；交易日和取数时间仍分别记录，历史发布时间保持未知。

`archiveRiskWarningObservations` 将 Tushare `stock_st` 的单日风险警示名单写入 `.ohquant/data/risk-warning-archives-v1/`。归档保留交易日、采集时刻、端点、供应商股票名称和风险警示分类。同一股票的不同分类按行保存，供应商成功返回的空列表也有引用。`loadRiskWarningArchive` 校验种类和内容摘要后离线读取。历史覆盖标记为未知，股票池筛选由 Runtime 处理。

`archiveMoneyFlow` 将 Tushare `moneyflow` 的单日沪深个股资金流写入 `.ohquant/data/money-flow-archives-v1/`。每个版本保留交易日、采集时刻、供应商原有顺序、四档买卖量与金额、独立报告的净流入，以及手和万元的原始单位。成功返回的空列表也有版本。`loadMoneyFlowArchive` 校验归档种类和内容摘要后读取，采集版本的覆盖范围和供应商首发时间保持未知。

`archivePopularityList` 将扶摇历史人气榜写入 `.ohquant/data/popularity-archives-v1/`。归档保留上海自然日、该日零点、实际采集时刻、供应商名次和行顺序。空榜也有有效引用。`loadPopularityArchive` 按种类和内容摘要读取归档，超过供应商保留期限后仍可重开本地已有版本。归档中的自然日和零点无法证明榜单的首发时间。

每日涨跌停价可通过 `archiveDailyTradingLimits` 保存为独立的 `daily-trading-limits` 归档。每批包含同一 A 股标的、请求区间、按日排序的昨收和上下限、Tushare `stk_limit` 来源及观察时间。价格单位为元，保留供应商返回的空值。归档有自己的版本和内容摘要，文件位于 `.ohquant/data/trading-limit-archives-v1/`。 `loadDailyTradingLimitArchive` 只读给定引用，校验种类、摘要和记录，损坏或缺失时直接失败。该归档保存供应商价格，阈值容差和信号由 Quant 计算。

Storage 的 `archiveObservations` 接收同一标的、来源、端点、观察时间和数据类型的一批 Source v1 日线、分钟线或复权因子观察；K 线还要求同一周期和复权口径。每批必须非空、时间戳不重复。复权因子跨标的结果须按标的拆批。当前只接受无查询参数的相对端点路径，避免把凭证写入归档。数值、零值、空成交额与未知字段原样保留；不会补齐缺失数据或套用因子。

归档以规范化 JSON 的内容哈希作为不可变版本。`loadObservationArchive` 只能按返回的精确引用读取，并重新校验摘要、结构和身份；缺失或损坏时直接失败。相同内容可重复写入并得到相同引用；修订或不同观察时间形成不同版本。并发提交由文件锁协调，文件原子替换是提交点。记录位于独立的 `.ohquant/data/observation-archives-v1/`，不更改日线缓存或用户组合。

交易日键控日线使用独立的 `archiveTradingDateObservations` / `loadTradingDateArchive` 和 v2 引用，保存于 `.ohquant/data/observation-archives-v2/`。归档保留原始交易日、可为空的来源时间戳、请求范围、复权口径和来源单位，校验同一批的身份及上海交易日一致性。v1 引用和文件不变；v1 与 v2 不会相互回退或自动迁移。这只是显式存储接口，不执行采集，也不代表 Runtime、Host、界面或 TSP 同步已经接入。

归档只证明本应用保存了什么；它不是 TSP 传输、自动同步、增量进度、水位或覆盖完整性的证明，也不能把抓取时间当成供应商首次发布时间。运行时尚未自动调用该接口，旧研究消费者也不会自动使用它；这部分仍由 [#258](https://github.com/yangjingo/WhyJ-Quant/issues/258) 和 [#264](https://github.com/yangjingo/WhyJ-Quant/issues/264) 跟踪。

显式运行时入口 `collectObservations` 可使用当前配置的数据源采集一个标的的一类日线、分钟线或复权因子，返回空结果或已提交的精确归档引用；`replayObservations` 只按该引用读取，不访问供应商。调用方指定 UTC 毫秒窗口，K 线还指定周期与复权口径。失败或取消不会返回成功引用；已提交的记录不会因后续取消而回滚。调用方负责保留引用；现阶段没有自动调度、增量水位或 TSP 传输，返回成功不代表历史完整或数据已被既有研究消费者使用。

`collectTradingDateObservations` 是显式的交易日日线采集入口：按当前选定来源请求有界上海交易日区间，非空结果保存为版本 2 引用，空结果不写入。`replayTradingDateObservations` 只读取该精确引用，不访问供应商。它不生成时间戳、不使用查询缓存或后备供应商；Host 和设置界面尚未接入此入口，真实权限和历史覆盖仍待验证。
